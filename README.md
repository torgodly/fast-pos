# فاست بوس — نظام نقاط البيع

نظام نقاط بيع بسيط للمطعم والكافيه:

- شاشة رئيسية ببطاقتين (مطعم / كافيه)
- دخول الموظفين برمز PIN فقط (يعملون في أي فرع)
- السفرادجي يفتح فواتير الطاولات ويضيف الأصناف ويرسل للمطبخ
- الكاشير يحصّل الفواتير (نقدي / بطاقة) ويدعم البيع السريع
- طباعة صامتة عبر الشبكة لطابعات XPrinter (بدون حوار المتصفح)
- لوحة إدارة للأصناف والطاولات والموظفين والطابعات والتقارير

## التشغيل على Windows (السيرفر)

**مهم:** استخدم **Node.js 24 LTS** أو **22.13 LTS فأحدث**.
`better-sqlite3` يحتاج نسخة جاهزة (prebuild) أو Python + أدوات بناء C++.

1. ثبّت Node **24 LTS** من [nodejs.org](https://nodejs.org/) أو استخدم Node 22.13 LTS فأحدث.
2. في PowerShell:

```powershell
node -v
# يجب أن يظهر v24.x أو v22.13.x فأحدث

cd C:\fast-pos
npm install
npm run build
npm start
```

إذا فشل تثبيت `better-sqlite3` لعدم توفر نسخة جاهزة، ثبّت **Python 3** + **Visual Studio Build Tools** (Desktop development with C++)، ثم أعد `npm install`.

لا تنسخ مجلد `node_modules` من Mac/Linux؛ يجب تثبيت الاعتماديات على Windows حتى تتطابق الملفات الأصلية مع النظام وإصدار Node المستخدم.

## تفعيل النظام

يبدأ النظام بفترة تجريبية مدتها **7 أيام** من أول تشغيل. بعد انتهائها، تتوقف عمليات نقاط البيع للموظفين، بينما تبقى لوحة الإدارة وصفحة التفعيل متاحتين.

### إعداد مفاتيح الترخيص (مرة واحدة)

أنشئ المفاتيح على جهاز مسؤول وآمن، وليس على سيرفر نقاط البيع:

```powershell
node scripts/license.mjs keygen --out-dir "C:\fast-pos-license-keys"
```

احتفظ بملف `license-private.pem` خارج سيرفر POS ولا تشاركه. تختار واجهة الترخيص المفتاحين مرة واحدة وتحفظ مساريهما محلياً. عند تنفيذ `npm run build`، يُنسخ **المفتاح العام فقط** إلى `data\license-public.pem` ليستخدمه إصدار POS. أما عند تشغيل السيرفر خارج مجلد البناء أو عند النشر اليدوي، يمكنك تحديد مسار المفتاح العام في `.env.local`:

```env
ACTIVATION_PUBLIC_KEY_FILE=C:\fast-pos-keys\license-public.pem
```

أعد تشغيل السيرفر بعد إعداد المفتاح العام.

يمكن بدلاً من الأوامر استخدام واجهة Windows الرسومية. تتذكر الواجهة المفتاح الخاص والعام المختارين في ملف إعدادات محلي داخل `%APPDATA%`، وتحتوي على تبويب لإصدار الترخيص وتبويب للتحقق من التوقيع وتاريخ الصلاحية ومعرّف التثبيت. شغّل `npm run license:gui` للتجربة، أو أنشئ ملفاً تنفيذياً مستقلاً:

```powershell
npm run license:gui:build
```

ينتج الملف `release\license-generator\Fast-POS-License-Generator.exe`. أثناء البناء، أدخل عبارة مرور قوية (12 حرفاً على الأقل) مرتين. تُضمّن نسخة مشفرة من المفتاح الخاص والمفتاح العام المطابق داخل EXE؛ ولا تحفظ عبارة المرور في الملف التنفيذي أو الإعدادات. عند إصدار كل ترخيص، يطلب البرنامج عبارة المرور لفك المفتاح في الذاكرة. احفظ عبارة المرور منفصلة عن EXE؛ فمن يحصل على الاثنين يستطيع إصدار تراخيص. يتطلب بناء EXE تثبيت Python والاعتماديات من `desktop\license-generator\requirements.txt`، أما تشغيله فلا يتطلب Node.js أو Python ولا ملفات المفاتيح الأصلية.

كل أمر `npm run build` ينسخ المفتاح العام المختار في إعدادات الواجهة إلى `data\license-public.pem` بعد التحقق من أنه مفتاح Ed25519؛ ولا يُنسخ المفتاح الخاص. لذلك تستخدم إصدارات POS المستقبلية نفس المفتاح العام للتحقق من التراخيص. عند البناء على جهاز آخر، اختر `ACTIVATION_PUBLIC_KEY_FILE` للإشارة إلى المفتاح العام، أو استخدم إعدادات الواجهة المحلية.

### إصدار ترخيص وتفعيله

1. سجّل الدخول كمدير وافتح **الإدارة ← التفعيل**، ثم انسخ معرّف التثبيت الظاهر.
2. على جهاز مسؤول الترخيص، أنشئ رمزاً موقعاً. حدّد تاريخ انتهاء UTC:

```powershell
node scripts/license.mjs issue --private-key "C:\fast-pos-license-keys\license-private.pem" --installation-id "UUID_FROM_ACTIVATION_PAGE" --expires-on "2027-12-31" --out "license.txt"
```

3. الصق محتوى `license.txt` في صفحة التفعيل واضغط **تفعيل الترخيص**.

التراخيص موقعة وتُتحقق محلياً؛ لا يحتاج POS إلى اتصال إنترنت. يرتبط كل ترخيص بتثبيت واحد وينتهي بنهاية يوم التاريخ المحدد بتوقيت UTC. إلغاء التفعيل من لوحة الإدارة محلي فقط، ولا يبطل الترخيص عن بُعد على تثبيت غير متصل. تُحفظ بيانات التفعيل مستقلة عن إعادة تهيئة المبيعات والطابعات.

## شعار الفاتورة

من **الإدارة ← الإعدادات ← شعار الفاتورة** يستطيع المدير رفع شعار بصيغة PNG أو JPG أو WebP أو GIF (بحد أقصى 5 ميغابايت). تُحوّل الصورة وتُحفظ في مجلد `data` وتُستخدم للطباعة الحرارية ونسخة الفاتورة في المتصفح. يمكن استعادة الشعار الافتراضي من الصفحة نفسها.

## التشغيل (محلي على الشبكة)

شغّل السيرفر على جهاز دائم داخل المطعم/الكافيه (mini PC) على نفس شبكة Wi‑Fi الخاصة بالأجهزة والطابعات:

```bash
bun install
bun run dev
# أو للإنتاج:
bun run build && bun start
```

`npm start` يستمع على `0.0.0.0:3000` ليتصل به الـ iPad عبر الشبكة.

**ملاحظة للشبكة المحلية (HTTP):** لا تفعّل `Secure` على الكوكيز. اترك `COOKIE_SECURE` غير معرّف.  
إذا استخدمت HTTPS لاحقاً: `set COOKIE_SECURE=true` قبل التشغيل.

افتح من الـ iPad: `http://IP-الجهاز:3000`  
قاعدة البيانات SQLite تُنشأ تلقائياً في `data/pos.db` مع بيانات تجريبية غنية:
أصناف، طابعات، طاولات، فواتير مفتوحة/مدفوعة/ملغاة لتجربة التقارير والإقفال.

لحذف القاعدة وإعادة التهيئة:

```bash
rm -f data/pos.db data/pos.db-shm data/pos.db-wal
bun run dev
```

## بيانات الدخول التجريبية

### الإدارة
- الرابط: `/admin/login`
- المستخدم: `admin`
- كلمة المرور: `admin123`

### الموظفون (يعملون في المطعم والكافيه)
- سفرادجي أحمد: `1111`
- كاشير سارة: `2222`
- سفرادجي يوسف: `3333`
- سفرادجي مريم: `4444`
- كاشير خالد: `5555`
- سفرادجي ليلى: `6666` (معطّل — للتجربة)

## الطابعات

### مطبخ (شبكة)
الطباعة من **سيرفر الـ POS** مباشرة إلى IP الطابعة (منفذ `9100`).

### كاشير — طريقتان

| النوع | من أين تطبع | إعداد |
|--------|-------------|--------|
| **شبكة** | السيرفر → IP الطابعة | IP ثابت + منفذ 9100 |
| **USB محلي** | **جهاز الكاشير Windows** → USB | وكيل الطباعة (بدون نافذة) |

#### USB على PC الكاشير — 3 خطوات
1. في Windows: اجعل طابعة الإيصال **الافتراضية**
2. على PC الكاشير: شغّل **`SETUP.bat`** مرة واحدة (من `tools\cashier-print-agent`)
3. في الإدارة: طابعة كاشير → **USB** → اترك IP فارغاً

يفتح الكاشير من **نفس PC** — بدون config ولا اسم طابعة.

### إعداد عام
1. من الإدارة ← **الطابعات**: أضف طابعات المطبخ (شبكة) وطابعة **فاتورة كاشير** لكل قسم (مطعم / كافيه).
2. **اختبار طباعة** يعمل لطابعات الشبكة فقط.
3. من **الأصناف**: اربط **التصنيفات** بطابعات المطبخ — كل الأصناف تحت التصنيف تطبع على نفس الطابعة.
4. الموظف يختار **مطعم** أو **كافيه** من الصفحة الرئيسية — الطباعة تلقائية على طابعة ذلك القسم.

### عند فشل الطباعة (للموظفين)
1. هل الطابعة تعمل وفيها ورق؟
2. هل الـ iPad يفتح نظام الـ POS؟
3. أعد تشغيل الطابعة → الراوتر → جهاز السيرفر.

الدفع يُسجَّل حتى لو فشلت طباعة الفاتورة — ستظهر رسالة تحذير واضحة على الشاشة.

## الجلسات والصلاحيات

- كل مستخدم له **جلسة واحدة** (مدير / سفرادجي / كاشير).
- السفرادجي والكاشير **لا يصلون** للإدارة حتى يسجّلوا الخروج.
- المدير يُوجَّه تلقائياً للوحة الإدارة ولا يدخل شاشات الـ PIN.
- الكوكيز تعمل على HTTP داخل الشبكة المحلية (بدون HTTPS).

## تهيئة جزئية (مدير فقط)

في لوحة الإدارة ← أسفل القائمة: **تهيئة المبيعات والطابعات**

يتطلب كلمة مرور المدير + كتابة `RESET`.

**يُحذف:** المبيعات، الطابعات، الموظفون (سفرادجي/كاشير).

**يُحفظ:** الأصناف، التصنيفات، الطاولات، حساب المدير.

## التقارير

في الإدارة ← **التقارير** يمكنك عرض:
- إجمالي المبيعات ونقدي/بطاقة
- الكمية المباعة حسب **الصنف**
- الكمية المباعة حسب **المجموعة** (التصنيف) مثل الحلويات
